# 曾記麻辣燙｜員工打卡系統

手機優先的員工打卡 Web App。員工第一次登入後手機就被記住，之後打開網站按「打卡」就完成，老闆 / 老闆娘的手機會立刻收到推播通知，員工自己也會收到收據。

- **員工**：一鍵打卡（自動判斷上班 / 下班）、看全店月曆班表、在月曆上看自己的排班 vs 實際打卡與每天賺多少、選日期區間查薪水與是否已領、改密碼。**看不到別人的打卡與薪水。**
- **老闆 / 老闆娘**：看得到所有人；在月曆上排班、改班、登記請假、一鍵「套用固定班」；設定時薪；一鍵發放薪資（金額自動算好）；通知中心（打卡、排班異動、請假、發薪）；匯出 Excel；管理員工與手機綁定。

## 技術選擇

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| 框架 | **SvelteKit 3 + Svelte 5 + TypeScript** | 前後端同一個專案：頁面用 Svelte，寫資料庫、發推播都在 SvelteKit 的 server 端（`+page.server.ts` 的 form actions），金鑰不會進到瀏覽器。表單在沒有 JS 的情況下也能送出，手機網路不穩時比較耐用。 |
| 樣式 | **Tailwind CSS 4** | 設計 token（紅湯色、宣紙底、墨色）集中寫在 `src/routes/layout.css` 的 `@theme`，改色只要改一個地方。 |
| 資料庫 | **MySQL（liam.name404.com:13306）+ Drizzle ORM** | `liam.name404.com` 是自架主機（nginx + phpMyAdmin + 對外 MySQL 13306）。Drizzle 有型別安全的查詢，而且能用 `npm run db:push` 直接建表。 |
| 推播 | **標準 Web Push（VAPID）+ PWA** | 不用 LINE、也不用 Firebase 帳號：金鑰自己產生，免費、沒有則數限制。Android / 電腦直接收；iPhone 加入主畫面後也能收（iOS 16.4 以上）。Firebase 網頁版推播底層用的也是同一套機制。 |
| 部署 | `@sveltejs/adapter-node` | 產出一般的 Node 伺服器，可以直接跑在同一台主機上，放在 nginx 後面。 |

需要 **Node.js 22.17 以上**（SvelteKit 3 的要求）。

## 快速開始

```bash
npm install
cp .env.example .env      # 填入 DATABASE_URL
npx web-push generate-vapid-keys   # 產生推播金鑰，貼進 .env 的 VAPID_*
npm run db:push           # 依 src/lib/server/db/schema.ts 建立資料表
npm run dev
```

打開 http://localhost:5173 。資料庫裡還沒有任何人時會自動進入註冊頁（「歡迎使用」），老闆註冊時勾選 **「我是老闆」**。

**帳號怎麼來**
- **自己註冊**：首頁和登入頁都有「註冊」。店裡還沒有老闆時，註冊頁會出現「我是老闆」可以勾；**已經有老闆之後這個勾選就不會再出現**，之後註冊的人一律是員工（伺服器端也會再檢查，硬送也沒用）。註冊完這支手機就直接綁定，老闆會收到「新員工註冊了」的通知，記得去設定時薪。
- **老闆幫忙開**：「員工」分頁 →「新增員工」，填名字、帳號、初始密碼。
- **給老闆權限**（例如老闆娘）：她先註冊成員工 → 老闆到「員工」分頁點她 → 身分選「老闆權限」→ 儲存。她的手機會收到「你有老闆權限了」，底部會多出「員工」和「管理」分頁；之後也可以用同一個地方收回。
- **排班權限**（例如組長）：「員工」分頁點他 → 打開「排班權限」→ 儲存。他就能在「月曆」→「全店班表」新增、修改、刪除**員工**的班、登記請假、套用固定班；但**不能改老闆 / 老闆娘的班**、不能補登打卡、看不到別人的打卡和薪水、不能發薪或管理員工。他每改一次班，老闆都會收到通知（例如「李俊逸 新增了 周冠穎 10/28 17:00–20:00 的班」）。
- 注意：知道網址的人都能註冊成員工（看得到全店班表，看不到別人的薪水）。有不認識的人註冊，老闆可以在「員工」分頁把他停用。

> 用手機測試：`npm run dev -- --host` 後，手機連同一個 Wi-Fi，打開 `http://<電腦IP>:5173`。

## 環境變數

| 變數 | 必填 | 說明 |
| --- | --- | --- |
| `DATABASE_URL` | ✅ | `mysql://帳號:密碼@liam.name404.com:13306/zengji_punch` |
| `VAPID_PUBLIC_KEY` | | 推播公鑰（會送到瀏覽器）。沒填就不推播，打卡照常記錄。 |
| `VAPID_PRIVATE_KEY` | | 推播私鑰，只放伺服器 |
| `VAPID_SUBJECT` | | `mailto:你的email`，推播服務（Google / Apple）需要聯絡方式 |

環境變數在 `src/env.ts` 用 SvelteKit 3 的 `defineEnvVars` 宣告，程式裡從 `$app/env/private` 取用，**只存在伺服器端**。

## 資料庫設定（liam.name404.com）

建議另外開一個資料庫和專用帳號，不要跟其他專案共用 root。用 phpMyAdmin（`https://liam.name404.com/phpmyadmin/`）或 SSH 進主機執行：

```sql
CREATE DATABASE zengji_punch CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'zengji'@'%' IDENTIFIED BY '換成一組長密碼';
GRANT ALL PRIVILEGES ON zengji_punch.* TO 'zengji'@'%';
FLUSH PRIVILEGES;
```

> 如果 app 之後跟 MySQL 部署在同一台主機，可以把帳號限制成 `'zengji'@'localhost'`，`DATABASE_URL` 改連 `127.0.0.1:3306`，就不必經過對外的 13306。

接著在專案裡執行 `npm run db:push`，會建立 10 張表。不方便從電腦連 13306 的話，也可以把 [`drizzle/0000_init.sql`](drizzle/0000_init.sql) 貼到 phpMyAdmin 的 SQL 分頁執行，結果一樣。

| 資料表 | 內容 |
| --- | --- |
| `employees` | 員工與老闆（姓名、帳號、scrypt 雜湊密碼、角色、代表色、時薪、是否在職） |
| `devices` | 手機綁定（只存 token 的 SHA-256、裝置名稱、綁定 / 最後使用 / 解除時間） |
| `punches` | 打卡紀錄（時間；員工自己打的是 `app`、老闆補登的是 `manual`；有開打卡範圍時記下離店家幾公尺） |
| `shifts` | 班表（日期、起訖時間、備註、是否請假） |
| `shift_templates` | 固定班（每人每週哪幾天、幾點到幾點） |
| `notifications` | 給老闆看的動態通知 |
| `push_subscriptions` | 每支手機的推播訂閱（一個人可以有好幾台） |
| `reminders` | 已送過的自動提醒，避免重複 |
| `settings` | 店家設定（目前是打卡範圍：座標、半徑、開關） |
| `payouts` | 薪資發放（期間、金額、月結 / 週結 / 其他、備註、記錄人） |

時間一律以 UTC 存進資料庫（連線設定 `timezone: 'Z'`），畫面上統一換算成台灣時間。之後改了 `schema.ts` 再跑一次 `npm run db:push` 即可。

## 手機推播通知設定

用的是瀏覽器內建的 **Web Push**（不用 LINE、不用 Firebase）。打卡、排班、發薪時，伺服器直接推到大家的手機。

**1. 產生金鑰（只要做一次）**

```bash
npx web-push generate-vapid-keys
```

把產生的 Public Key / Private Key 填進 `.env` 的 `VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`，`VAPID_SUBJECT` 填 `mailto:你的email`，重啟服務。**金鑰換掉的話，所有人都要重新開啟一次通知**，所以正式上線後就不要再換。

**2. 每支手機開啟通知（每個人做一次）**

- **Android / 電腦（Chrome、Edge）**：登入後首頁會出現「開啟手機通知」，按「開啟」→「允許」就好。
- **iPhone（iOS 16.4 以上）**：Safari 一般分頁收不到推播，要先：
  1. 用 **Safari** 打開網站
  2. 點分享按鈕 → **加入主畫面**
  3. 從主畫面的「曾記打卡」圖示打開，登入後按「開啟通知」→「允許」
  
  **iPhone 最好「先加入主畫面、再登入」**：主畫面 App 和 Safari 分頁的登入狀態不一定共用（iOS 17 以上會在加入時複製一份，舊版不會）。如果員工已經在 Safari 綁定，主畫面 App 卻顯示沒登入，登入時會被當成第二支手機擋下，這時請老闆「解除綁定」，再讓他在主畫面 App 裡登入。iPhone 用 Safari 打開登入頁時，畫面上也會提醒這件事。
- 「我的」或「管理」頁可以看狀態、送測試通知、關閉通知。後台員工列表會顯示每個人有沒有開通知。

**3. 誰會收到什麼**

| 事件 | 老闆 / 老闆娘 | 當事員工 |
| --- | --- | --- |
| 員工打卡 | 「周冠穎 上班打卡 16:02」 | 「上班打卡成功」收據 |
| 排班 / 改班 / 刪班 | 有（做這件事的老闆自己不會收到） | 「你的班表有更新」 |
| 套用固定班 | 有 | 「11 月班表排好了，你有 N 個班」 |
| 請假 | 有 | 「已登記請假」 |
| 老闆補登打卡 | 有 | 「老闆幫你補登了打卡」 |
| 上班時間過 5 分鐘還沒打卡 | 只記在通知中心 | 「是不是忘記打上班卡了？」 |
| 過了晚上 12 點還沒下班卡 | 「周冠穎 10/16 沒打下班卡」 | 「昨天忘記打下班卡」 |
| 發薪 | 有 | 「薪水發囉！10/12–10/16 共 $2,013」 |

點通知會直接打開對應的頁面（後台、月曆或薪資）。所有事件也都會記在「管理」最上方的通知中心，就算手機沒開通知也查得到。

> 推播一定要 **HTTPS**（本機 `localhost` 開發除外）。手機關機或沒網路時，推播服務會保留 24 小時，開機後補送。

## 裝置綁定與換手機流程

- 員工第一次在手機上登入，系統會發一組隨機 token 存在 httpOnly cookie（資料庫只存它的 SHA-256），這支手機就綁定了。之後打開網站直接按「打卡」即可，不必再登入。
- cookie 每次造訪都會自動續期（瀏覽器上限約 400 天），正常使用下不會過期。
- **一般員工同時只能綁一支手機**。已經綁定的帳號在別支手機登入會被擋下，避免代打卡。一支已綁定的手機也不能再登入別人的帳號。
- 老闆帳號可以同時在多支裝置登入，也可以自己登出。

**換手機（由老闆協助）**

**「員工」分頁**最上面是 **「手機綁定」** 總覽：每個人綁在哪支手機、哪天綁定、最後使用時間，旁邊就是 **「轉移帳號」** 按鈕。

> 手機型號：Android 的 Chrome / Samsung 瀏覽器會顯示真正型號（例如「Pixel 8」「SM-S9210」）；**iPhone 只會顯示「iPhone」**，Apple 不讓網頁知道型號。型號只是給老闆看的，系統認手機靠的是登入時存在手機裡的那把鑰匙，不是型號。

1. 老闆按該員工的 **「轉移帳號」**（點開員工也有同一顆按鈕）。
   - 舊手機**立刻**不能打卡，打開網站會回到登入頁。
   - **這次**被轉走的舊手機**不能再用同一組帳號登回去**（系統認得出是哪支手機）。如果老闆之後又轉移一次（例如 A → B，又從 B 轉回來），被擋的只會是最近一次被轉走的那支（B），A 可以重新登入當新手機。
   - 舊手機的推播通知也一併停掉。
   - 總覽上這個人會顯示「等新手機登入」。
2. 員工用新手機打開網站 →「登入」，輸入**原本的帳號密碼**，新手機就綁定了。打卡紀錄、班表、薪資都跟著帳號，全部都在。
3. 老闆會收到「周冠穎 已在新手機（iPhone · Safari）登入，帳號轉移完成」的通知。新手機記得再開一次通知。

**忘記密碼**：老闆在同一個畫面 **「重設密碼」**，舊手機綁定會一併解除，員工用新密碼重新登入。

**員工自己改密碼**：「我的」→ 修改密碼。改完後所有綁定都會解除，需要用新密碼重新登入一次。

**離職**：「停用這位員工」，綁定會解除也無法再登入；歷史紀錄保留。

> 提醒員工：用手機的**一般瀏覽器**（Safari / Chrome）打開並「加入主畫面」，不要用 LINE 內建瀏覽器（收不到通知，綁定也可能不穩）。清除瀏覽器資料或用無痕模式會讓綁定消失，這時一樣找老闆解除綁定。

## 打卡、排班與薪資規則

**打卡**
- **每天以「最早一筆 = 上班卡、最晚一筆 = 下班卡」計算**，中間不小心多按的都不影響（月曆點開那天會列出來，但不算錢）。
- 首頁按鈕：今天還沒打過顯示「上班打卡」，打過之後顯示「下班打卡」；下班後再按一次就會**更新**下班時間。
- 一天以台灣時間 0:00 切開。60 秒內連按會被擋下，避免手滑。
- **員工不能早於班表的下班時間打下班卡**（例如排 16:00–19:00，19:00 前按下班會被擋）。要提早走，請老闆在月曆上改班表或把那天標成「請假」。首頁會提示「19:00 後可以打下班卡」。老闆 / 老闆娘不受此限制。

**打卡範圍（要在店家附近才能打卡）**
- 店家位置**固定**在 `25.1477191, 121.3990287`（寫在 `src/lib/server/geofence.ts` 的 `STORE`，搬店時改這裡），範圍**一律開著**。
- 老闆 / 老闆娘在「管理」→「打卡範圍」選半徑（50–500 公尺，建議 100–150）按儲存就好，旁邊有連結可以在 Google 地圖確認店家位置。
- 員工首頁會即時定位：離店家太遠時打卡按鈕變灰色、上鎖不能按，下面寫「離店家 1.0 公里，要在 150 公尺內才能打卡」；走進範圍內按鈕就會解鎖。
- 伺服器也會再檢查一次手機送來的位置，所以就算有人改網頁把按鈕解鎖也打不了卡。手機定位誤差最多幫忙抵掉 50 公尺（室內 GPS 常常會飄）。
- 每筆打卡會記下當時離店家幾公尺，老闆在月曆點開那天可以看到（例如「📍35m」）。
- 只限制員工，老闆 / 老闆娘不受限；老闆補登打卡也不受影響。
- 員工手機要允許網站使用「位置」。被拒絕時首頁會告訴他去哪裡打開。定位只在打開首頁時使用，不會在背景追蹤。
- 注意：GPS 位置可以用特殊 App 假造，這個功能是防止「人在家就打卡」，不是百分之百防作弊。

**自動提醒**（伺服器每分鐘檢查一次，同一件事一天只提醒一次）
- **忘記打上班卡**：今天有排班（沒請假），班表上班時間過了 5 分鐘還沒打卡 → 推播提醒**員工本人**「是不是忘記打上班卡了？」，通知中心也會記一筆。
- **沒打下班卡**：過了晚上 12 點，前一天只有上班卡、沒有下班卡 → 推播給**老闆、老闆娘和員工本人**，請老闆補登下班時間。
- 只針對員工，老闆 / 老闆娘不會被提醒。提醒的分鐘數在 `src/lib/server/reminders.ts` 的 `MISSING_IN_AFTER_MIN` 可以調。
- 提醒靠伺服器裡的計時器，所以伺服器要一直開著（用 PM2 / systemd 常駐）；`reminders` 資料表會記住送過哪些，重啟也不會重複發。

**月曆**（底部「月曆」分頁）
- 月曆從**週日**開始；週六、週日和節日的日期是紅字，節日會在日期下面寫名稱（例如 10/10 國慶日）。補假、小年夜這類只有公家機關放的日子用淡紅色。
- 「全店班表」：每格列出當天誰上班，色塊是實心代表已打卡，淡色代表只有排班，刪除線代表請假。
- 個人檢視：每格顯示「排班時間 / 上班卡 / 下班卡 / 當天薪資」，已發薪的日子有綠色勾勾與底線；上方顯示當月薪資、已領、未領、遲到 / 缺卡。
- 點任何一天可以看詳細：排班、實際打卡、計薪時數 × 時薪 = 金額、是否已領。老闆可以在這裡排班、改班、請假、補登或刪除打卡。
- **固定班**：在「員工」分頁點員工 → 勾選每週固定上班的日子與時間。之後到月曆按「套用固定班」，整個月就排好了（已經排的日子不會被覆蓋）。

**薪資計算**（以時薪計）
- 每段「上班卡 → 下班卡」算一次，算到分鐘，金額四捨五入到元。
- 比班表**早到**的時間不算，從班表上班時間開始算；**遲到**就從實際打卡時間算。
- **晚走照算**：例如排 16:00–19:00、19:30 下班、時薪 200 → 3.5 小時 × 200 = **$700**。
- 沒排班卻有打卡，照實際時間算；還沒打下班卡的那段先不算。
- 請假的日子不用打卡、不算缺勤、不計薪。
- **國定假日上班薪水 ×2**（勞基法第 39 條）。月曆和薪資明細會標「國定假日 ×2」。只有勞基法的國定假日才算（元旦、228、除夕、春節、兒童節、清明、勞動節、端午、中秋、教師節、國慶、光復節、行憲紀念日）；補假、小年夜、調整放假不算。老闆可以在「管理」→「國定假日雙倍薪」關掉。
- 節日資料來自**人事行政總處「政府行政機關辦公日曆表」**（經 [ruyut/TaiwanCalendar](https://github.com/ruyut/TaiwanCalendar) 整理，透過 jsDelivr 取得）。伺服器抓下來存在 `settings` 表，一週更新一次；新的一年資料通常在前一年 6 月公告後就會有。抓不到時會用快取，再不行就只標國曆固定日期的節日（農曆節日會缺）。
- 提醒：勞基法還有「國定假日遇到例假日要補休」等細節，雙倍薪只照「實際上班的那天」算；有特殊約定（例如調移假日）請老闆自行在發薪時調整金額。
- 上班卡比班表晚 5 分鐘以上標「遲到」；有上班沒下班標「缺卡」；有排班但沒打卡標「未到」。老闆 / 老闆娘排班但沒打卡不算缺勤。

**發薪**（底部「薪資」分頁）
- 選員工、選區間（今天 / 本週 / 上週 / 本月 / 上月或自訂），看每天的工時與金額、已領與未領。
- 老闆按「發放未領的 $X」：期間與金額自動帶入（可手動加獎金），確認後這段日子在月曆上標成「已領」，並推播通知該員工與其他老闆。

**通知中心**（「管理」最上方）
- 打卡、補登、排班異動、請假、時薪變更、發薪都會記一筆；底部「管理」分頁會顯示未讀數。

**匯出 Excel**（「管理」→ 匯出 Excel）
- 選日期區間下載 `.xlsx`，內含三個工作表：薪資總表（每人工時、應領、已領、未領、遲到、缺卡、請假）、每日明細（排班、上下班卡、計薪時數、金額、狀態）、發放紀錄。

## 部署到 Vercel

專案會自動判斷：在 Vercel 上建置時用 `@sveltejs/adapter-vercel`（函式放在**香港 hkg1**，離台灣的資料庫最近），在自己主機上就用 adapter-node，不用改程式。

1. Vercel 匯入 GitHub repo `doraeyi/zengji-punch`，Framework Preset 選 **SvelteKit**（或 Other 也可以，建置後會自動用 `.vercel/output`）。
2. **Settings → Environment Variables**，把 `.env` 裡這幾個貼上去（Vercel 支援直接貼整份 .env）：
   `DATABASE_URL`、`VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT`、`CRON_SECRET`
3. 重新部署。Vercel 給的網址本身就是 HTTPS，手機定位和推播都能用。
4. **自動提醒要另外設排程**：Vercel 沒有一直開著的伺服器，「忘記上班卡」「半夜沒下班卡」的檢查改成呼叫網址觸發。
   - 免費做法：到 [cron-job.org](https://cron-job.org) 建一個工作，每 1 分鐘 `GET https://你的網域/api/cron/reminders`，Header 加 `Authorization: Bearer <CRON_SECRET>`（或網址後面加 `?key=<CRON_SECRET>`）。
   - Vercel Pro 方案也可以用內建 Cron；免費（Hobby）方案的 Cron 一天只能跑一次，不夠用。
   - 沒設排程的話，打卡、推播、薪資都照常，只是不會有自動提醒。
5. 資料庫要讓 Vercel 連得到：目前用 `liam.name404.com:13306` 對外的 MySQL，Vercel 的機器 IP 不固定，所以防火牆不能只開特定 IP。

> 每次 push 到 GitHub 的 `main`，Vercel 就會自動重新部署。

## 部署（adapter-node）

```bash
npm run build
DATABASE_URL=... VAPID_PUBLIC_KEY=... VAPID_PRIVATE_KEY=... VAPID_SUBJECT=mailto:... \
PORT=3010 PROTOCOL_HEADER=x-forwarded-proto HOST_HEADER=x-forwarded-host ADDRESS_HEADER=x-forwarded-for \
node build
```

nginx 反向代理範例（建議用獨立子網域，例如 `punch.example.com`。如果要掛在子路徑，需要另外設定 SvelteKit 的 `paths.base`）：

```nginx
location / {
    proxy_pass http://127.0.0.1:3010;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

必須使用 **HTTPS**（綁定用的 cookie 在正式環境需要 secure，推播與 Service Worker 也只能在 HTTPS 下運作）。

> adapter-node 預設把請求當成 `https`，再用它比對表單的 Origin（CSRF 防護）。所以直接用 `http://localhost` 連 `node build` 時，登入會回 403，這是正常的。本機測試請用 `npm run dev`；正式環境放在 HTTPS 的 nginx 後面，並設好上面的 `PROTOCOL_HEADER` / `HOST_HEADER`。
